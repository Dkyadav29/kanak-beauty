Kanak Beauty Academy: production deployment runbook

Every step and command to run the platform for real students: one AWS EC2 server (Django API + MariaDB), AWS SES for email, Razorpay for payments and Cloudflare for the website. Written 25 October 2026 against backend commit b0aab36 and later.

0Overview

Website (frontend)React app on Cloudflare Workers, built from GitHub Dkyadav29/kanak-beauty on every push to main. Served at https://kanakbeautyservice.com.
API (backend)Django + Gunicorn on AWS EC2 (Ubuntu 24.04), behind Nginx with a Let's Encrypt certificate. Served at https://api.kanakbeautyservice.com/api/v1. Code from GitHub Dkyadav29/kanak-beauty-backend.
DatabaseMariaDB on the same EC2 server, database kanak_academy. Uploaded files in media/ on the server disk.
EmailAWS SES (SMTP) sends OTP, password-reset and enrollment emails.
PaymentsRazorpay Checkout. A paid payment unlocks the course automatically (checkout verification plus signed webhook).
Daily jobsystemd timer runs complete_ended_batches at 00:30 to close finished batches and issue certificates.
How to read this guide

Each black box is a command. The label above it says where to run it: Your PC, Server (an SSH or EC2 Instance Connect terminal on the production EC2) or a dashboard. Replace the example values from section 1 wherever they appear.

Do the sections in order the first time. Sections 15 to 18 are for after go-live.

2Domain & DNS (Cloudflare)

  1. Cloudflare dashboard → Add a domain → enter kanakbeautyservice.com → Free plan. If the domain was bought elsewhere, change its nameservers at the registrar to the two Cloudflare shows, and wait until Cloudflare says Active.
  2. The website records are created automatically in section 12 when you attach the domain to the Worker.
  3. The API record is created in section 3, step 6, once the server has its fixed IP.
Keep the API record "DNS only" (grey cloud)

The API's Let's Encrypt certificate, Razorpay webhooks and per-student rate limits all work best when Cloudflare does not proxy api.. Only the website (the Worker) goes through Cloudflare.

3Create the EC2 server

  1. AWS console → top right, choose region us-east-2.
  2. EC2 → Key pairs → Create key pair: name kanak-prod-key, type RSA, format .pem. Save the downloaded file safely (for example on your Desktop). You cannot download it again.
  3. EC2 → Security groups → Create security group named kanak-prod-sg with these inbound rules:
    TypePortSourceWhy
    SSH22My IP onlyAdmin access. Never 0.0.0.0/0.
    HTTP800.0.0.0/0 and ::/0Certificate issuing and redirect to HTTPS
    HTTPS4430.0.0.0/0 and ::/0API traffic
    Do not open 3306 (MariaDB) or 8000 (Gunicorn); they stay private on the server.
  4. EC2 → Instances → Launch instance:
    • Name: kanak-prod
    • Image: Ubuntu Server 24.04 LTS (64-bit x86)
    • Type: t3.medium (2 vCPU, 4 GB) recommended; t3.small (2 GB) is the minimum
    • Key pair: kanak-prod-key
    • Network: existing security group kanak-prod-sg
    • Storage: 30 GB gp3, encrypted
    • Advanced → Termination protection: Enable
  5. EC2 → Elastic IPs → Allocate → select it → Associate with kanak-prod. This IP never changes, even after a reboot. Note it, for example 3.140.10.20.
  6. Cloudflare → your domain → DNS → Add record: type A, name api, IPv4 = the Elastic IP, proxy status DNS only, TTL Auto.

Connect to the server

Your PC (Git Bash or PowerShell)
ssh -i "$HOME/Desktop/kanak-prod-key.pem" ubuntu@api.kanakbeautyservice.com
Office network blocks port 22?

Use the browser terminal instead: EC2 → Instances → select kanak-prod → Connect → EC2 Instance Connect → Connect. Every "Server" command in this guide can be pasted there. (Instance Connect needs SSH from AWS's address range; if it fails, temporarily add the rule "SSH, port 22, source EC2_INSTANCE_CONNECT prefix list for us-east-2" to the security group.)

Create the database and the application user. Replace DB_PASSWORD_HERE with the database password from section 1:

Server

Prefer a managed database?

Amazon RDS for MariaDB adds automatic backups and failover at extra cost. Create it in the same VPC, allow port 3306 only from kanak-prod-sg, and put its endpoint in DB_HOST. Everything else in this guide stays the same.

The production settings refuse to start when something is unsafe

Startup stops with an error if DJANGO_SECRET_KEY or PAYMENT_WEBHOOK_SECRET is missing, if PAYMENT_GATEWAY=sandbox, or if PAYMENT_GATEWAY=razorpay without all three Razorpay values. Production also forces HTTPS, secure cookies and HSTS, and hides the API docs pages.

Until the Razorpay live keys arrive you can put the test keys (rzp_test_...) here, so the server starts and you can test end to end with no real money.

7Gunicorn service (systemd)

Runs the API in the background, restarts it if it crashes and starts it on boot. The update script restarts it by the name kanak-backend.

Server
sudo tee /etc/systemd/system/kanak-backend.service >/dev/null <<'UNIT'
[Unit]
Description=Kanak Beauty backend (Django + Gunicorn)
After=network.target mariadb.service
Wants=mariadb.service

[Service]
User=ubuntu
Group=www-data
WorkingDirectory=/home/ubuntu/apps/kanak-beauty-backend
EnvironmentFile=/home/ubuntu/apps/kanak-beauty-backend/.env
Environment=GUNICORN_BIND=127.0.0.1:8000
Environment=GUNICORN_WORKERS=3
ExecStart=/home/ubuntu/apps/kanak-beauty-backend/.venv/bin/gunicorn config.wsgi:application -c gunicorn.conf.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
UNIT

sudo systemctl daemon-reload
sudo systemctl enable kanak-backend

It is started in section 9, after the database tables exist. Rule of thumb for GUNICORN_WORKERS: 3 on t3.small, 5 on t3.medium.

8Nginx & HTTPS

Nginx receives HTTPS traffic and passes /api/ to Gunicorn. Only the API, static files and course thumbnails are reachable; everything else returns 404. Recordings and materials stay private and are only served through the API's signed links.

Server
sudo tee /etc/nginx/sites-available/kanak >/dev/null <<'NGINX'
server {
    listen 80;
    listen [::]:80;
    server_name api.kanakbeautyservice.com;

    client_max_body_size 10m;
    server_tokens off;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    location /static/ {
        alias /home/ubuntu/apps/kanak-beauty-backend/staticfiles/;
        expires 30d;
        access_log off;
    }

    # Public course thumbnails only; other uploads are served through signed API links.
    location /media/course-thumbnails/ {
        alias /home/ubuntu/apps/kanak-beauty-backend/media/course-thumbnails/;
        expires 7d;
    }

    location / {
        return 404;
    }
}
NGINX

sudo ln -sf /etc/nginx/sites-available/kanak /etc/nginx/sites-enabled/kanak
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

Get the HTTPS certificate

The DNS record from section 3 must already point to the Elastic IP. Check with nslookup api.kanakbeautyservice.com.

Server
sudo certbot --nginx -d api.kanakbeautyservice.com \
  --non-interactive --agree-tos -m admin@kanakbeautyservice.com --redirect

sudo systemctl status certbot.timer --no-pager   # auto-renewal is scheduled
sudo certbot renew --dry-run                     # renewal works

Certbot adds the HTTPS block to the same Nginx file and redirects HTTP to HTTPS. Certificates renew automatically about every 60 days.

10AWS SES email

SES sends registration OTPs, password-reset links and enrollment confirmations. Work in region us-east-2 (the same region as EMAIL_HOST).

10.1 Verify the domain

  1. AWS console → Amazon SES → Configuration → Identities → Create identity → Domain → kanakbeautyservice.com.
  2. Tick Use a custom MAIL FROM domain → mail.kanakbeautyservice.com (improves delivery to Gmail).
  3. DKIM: Easy DKIM, RSA 2048-bit, Publish DNS records to Route 53: off (your DNS is in Cloudflare). Create identity.
  4. SES now shows the DNS records. In Cloudflare → DNS, add each one, every one with DNS only (grey cloud):
    TypeNameValuePurpose
    CNAME ×3xxxx._domainkeyxxxx.dkim.amazonses.comDKIM (copy all three exactly from SES)
    MXmailfeedback-smtp.us-east-2.amazonses.com, priority 10Custom MAIL FROM
    TXTmailv=spf1 include:amazonses.com ~allSPF for MAIL FROM
    TXT_dmarcv=DMARC1; p=none; rua=mailto:admin@kanakbeautyservice.comDMARC (needed by Gmail/Yahoo)
  5. Wait until the identity shows Verified and DKIM Successful (usually under an hour).

10.2 Leave the sandbox (production access)

New SES accounts can only send to addresses you verified yourself. Students would get no email.

  1. SES → Account dashboard → Request production access.
  2. Mail type Transactional; website https://kanakbeautyservice.com.
  3. Use case, for example: "Kanak Beauty Academy sends one-time verification codes, password-reset links and course enrollment confirmations to students who register on our site. We send only to users who sign up themselves, expect under 1,000 emails per day, and handle bounces and complaints by disabling the address."
  4. Approval usually takes about one working day. Until then, verify your own test addresses under Identities → Email address.

10.3 Create SMTP credentials

  1. SES → SMTP settings → Create SMTP credentials → keep the suggested IAM user name → Create.
  2. Copy the SMTP user name and SMTP password. The password is shown only once. These are not your AWS login.
  3. Put them in the server .env as EMAIL_HOST_USER and EMAIL_HOST_PASSWORD, then restart:
Server
nano ~/apps/kanak-beauty-backend/.env      # set EMAIL_HOST_USER / EMAIL_HOST_PASSWORD
sudo systemctl restart kanak-backend

10.4 Send a test email

Server
cd ~/apps/kanak-beauty-backend && set -a; . ./.env; set +a
.venv/bin/python manage.py shell -c "from django.core.mail import send_mail; print(send_mail('Kanak SES test', 'SES works.', None, ['you@example.com']))"
# prints 1 when SES accepted it
If an email fails

The API never errors out because of email; it logs the failure and the student can press "Resend OTP". See the log with sudo journalctl -u kanak-backend -n 100 | grep -A5 "Could not send email". Common causes: still in the sandbox, unverified sender domain, wrong SMTP region, or a wrong SMTP password.

Optional: SES → Configuration sets → add one with SNS notifications for bounces and complaints so you can see addresses that bounce.

11Razorpay (live payments)

  1. Razorpay dashboard → switch to Live mode (needs completed KYC).
  2. Account & Settings → API Keys → Generate Key. Copy the Key ID (rzp_live_...) and Key Secret.
  3. Account & Settings → Webhooks → Add New Webhook:
    • URL: https://api.kanakbeautyservice.com/api/v1/payments/razorpay/webhook
    • Secret: a new long random string (save it)
    • Events: payment.authorized, payment.captured, payment.failed, order.paid
  4. Payment capture: Automatic (the backend also captures authorized payments itself, so either setting works).
  5. Put the three values in the server .env (RAZORPAY_KEY_ID, RAZORPAY_KEY_SECRET, RAZORPAY_WEBHOOK_SECRET) with PAYMENT_GATEWAY=razorpay, then sudo systemctl restart kanak-backend.
How a purchase unlocks the course

The student pays in the Razorpay popup → the website sends the signed result to /payments/razorpay/verify → the backend checks the signature and amount with Razorpay and activates the enrollment, places the student in an open batch and emails a confirmation. If the student closes the tab, the signed webhook does the same a moment later. Nobody has to approve anything by hand.

First real payment: buy the cheapest course yourself with a real card or UPI, check it unlocks, then refund it from Admin → Payments.

13Moving from UAT to production

UAT runs at 18.119.106.180 (https://18-119-106-180.sslip.io). Choose one option.

Option A (recommended): start clean

UAT holds test students, test payments and sample courses. Production starts empty and the admin re-creates the real trainers, courses, batches, hero slides, certificate settings and Refer & Earn rules. Nothing to copy; continue with section 14.

Option B: copy the UAT data

Use only if UAT already holds real content you want to keep. Copy the database and the uploaded files together.

UAT server
cd ~/apps/kanak-beauty-backend && set -a; . ./.env; set +a
MYSQL_PWD="$DB_PASSWORD" mysqldump --single-transaction --routines -u "$DB_USER" -h 127.0.0.1 "$DB_NAME" | gzip > ~/uat-db.sql.gz
tar czf ~/uat-media.tgz -C ~/apps/kanak-beauty-backend media
ls -lh ~/uat-db.sql.gz ~/uat-media.tgz
Your PC (copies via your machine)
scp -i "$HOME/Desktop/kanak-uat-key.pem"  ubuntu@18.119.106.180:~/uat-db.sql.gz ubuntu@18.119.106.180:~/uat-media.tgz .
scp -i "$HOME/Desktop/kanak-prod-key.pem" uat-db.sql.gz uat-media.tgz ubuntu@api.kanakbeautyservice.com:~/
Production server
sudo systemctl stop kanak-backend
cd ~/apps/kanak-beauty-backend && set -a; . ./.env; set +a
gunzip -c ~/uat-db.sql.gz | MYSQL_PWD="$DB_PASSWORD" mariadb -u "$DB_USER" -h 127.0.0.1 "$DB_NAME"
tar xzf ~/uat-media.tgz -C ~/apps/kanak-beauty-backend
bash scripts/uat_update.sh        # applies any newer migrations and restarts

Then remove test data that should not be live, as needed: test students, the sandbox payments (gateway_provider=sandbox) and their enrollments. To wipe all rows but keep admin users instead, use bash scripts/purge_db.sh --dry-run first, then bash scripts/purge_db.sh --yes --keep-admins (it takes a backup first).

Never copy the UAT .env

Production has its own secrets, domain, Razorpay live keys and SES credentials. Copying UAT data keeps its users' passwords working, which is expected; the JWT key change logs everyone out once.

Retire UAT afterwards

Once production is stable: stop the UAT instance (EC2 → Instance state → Stop) to save cost, or keep it for testing behind its own website. Release its Elastic IP if you terminate it.

14Go-live checklist

  • curl https://api.kanakbeautyservice.com/api/v1/health returns {"status": "ok"}.
  • http://api.kanakbeautyservice.com redirects to https://.
  • .env has DJANGO_SETTINGS_MODULE=config.settings.production and chmod 600.
  • Admin can log in at https://kanakbeautyservice.com/login.
  • Admin creates a trainer, a course (publish it), a batch with class time and Meet link, and a hero slide; the home page and footer show them.
  • New student registers with a real email and receives the OTP from SES.
  • "Forgot password" email arrives and the link opens https://kanakbeautyservice.com/reset-password?token=....
  • A real Razorpay payment unlocks the course, the student lands in a batch, the confirmation email arrives, and Admin → Payments shows it as Paid. Then refund it.
  • Razorpay dashboard → Webhooks shows recent deliveries with status 200.
  • Refer & Earn: Admin → Refer & Earn → Course rules are set as intended.
  • Certificate settings (template, signatures) are set and a test certificate looks right.
  • Daily backups run (section 16) and one restore was tested.
  • EC2 termination protection is on; AWS billing alarm created (Billing → Budgets).
  • The footer contact address/phone and the policy pages contain real details.

16Backups & restore

Daily database + media backup (14 days kept)

Server
sudo tee /usr/local/bin/kanak-backup >/dev/null <<'SH'
#!/usr/bin/env bash
set -euo pipefail
APP=/home/ubuntu/apps/kanak-beauty-backend
OUT=/home/ubuntu/backups
mkdir -p "$OUT"
set -a; . "$APP/.env"; set +a
STAMP=$(date +%Y%m%d-%H%M)
MYSQL_PWD="$DB_PASSWORD" mysqldump --single-transaction --routines -u "$DB_USER" -h "$DB_HOST" "$DB_NAME" | gzip > "$OUT/db-$STAMP.sql.gz"
tar czf "$OUT/media-$STAMP.tgz" -C "$APP" media
find "$OUT" -type f -mtime +14 -delete
SH
sudo chmod 755 /usr/local/bin/kanak-backup
( crontab -l 2>/dev/null; echo "15 2 * * * /usr/local/bin/kanak-backup >> /home/ubuntu/backups/backup.log 2>&1" ) | crontab -
/usr/local/bin/kanak-backup && ls -lh ~/backups

Off-server copies (strongly recommended)

  1. EBS snapshots: EC2 → Lifecycle Manager → Create policy → target the kanak-prod volume, daily, keep 7. Protects against losing the whole server.
  2. S3 copy: create a private bucket, for example kanak-prod-backups; IAM → Roles → create a role for EC2 allowing s3:PutObject on that bucket; attach it to the instance (Actions → Security → Modify IAM role). Then:
Server
sudo snap install aws-cli --classic
( crontab -l; echo "45 2 * * * aws s3 sync /home/ubuntu/backups s3://kanak-prod-backups/ --exclude '*.log'" ) | crontab -

18Rollback

Backend: go back to the previous commit

Server
cd ~/apps/kanak-beauty-backend
git log --oneline -5                       # find the last good commit, e.g. b0aab36
/usr/local/bin/kanak-backup                # safety backup first
git reset --hard b0aab36
.venv/bin/pip install -q -r requirements.txt
sudo systemctl restart kanak-backend

Do not run scripts/uat_update.sh while rolled back; it would pull main again. Fix or revert on GitHub (git revert <bad-commit> on your PC, push), then deploy normally.

If the bad release added a database migration

Rolling the code back does not undo the migration. Usually that is harmless (new columns are ignored by older code). If not, restore the database backup taken before the release (section 16).

Frontend

Cloudflare → Workers & Pages → kanak-beauty → Deployments → choose the last good deployment → Rollback (or "Promote" it). It switches instantly.
